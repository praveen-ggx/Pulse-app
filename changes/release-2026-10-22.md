## Migrations
- **Three, release set `prod-2026-10-22`, in this order:** `20261021094632_trips_hub_search.sql`, `20261022093720_ground_ops_trip_document_lock.sql`, `20261022100607_ground_ops_warehouse_indents_read.sql`. The first is described below; the other two:
  - `ground_ops_trip_document_lock`: function `ground_ops_trip_document_lock_reason(uuid, text)` (SECURITY DEFINER, anon has no EXECUTE) and trigger `trg_guard_trip_document_ground_ops` (before insert / update / delete on `trip_documents`; only Ground Ops members are affected; service role bypasses). Tested on a throwaway local Postgres 17 (20 scenarios).
  - `ground_ops_warehouse_indents_read`: SELECT-only policy `indents_ground_ops_select_assigned` on `indents` and a new body for `get_indents_delta`. Uses `ground_ops_can_see_trip` (already on prod). Checked read-only on prod data as a Ground Ops user: 422 indents, all of their warehouses' client.
  - Both additive; both rely only on functions already on prod (`compliance_awaiting_resubmit`, `ground_ops_can_see_trip`, `is_org_member`).
- `20261021094632_trips_hub_search.sql`: Adds the function `public.search_trips_for_org(uuid, text, integer)`, SECURITY DEFINER; execute revoked from public / anon, granted to authenticated / service_role. Additive: no table, column, row or existing function changes.
- Applied on preprod 21 Oct. Not on prod (checked read-only 22 Oct: 959 history rows, no `search_trips_for_org`).
- Pinned by `supabase/migrations/__tests__/prodRelease20261022Set.test.ts` (all three: list, order, SHA-256, no excluded or frozen version).
- Read-only prod dry-run (22 Oct, re-run after adding #27 / #28; CLI 2.95.4, prod never linked): "Would push these migrations: • 20261021094632_trips_hub_search.sql • 20261022093720_ground_ops_trip_document_lock.sql • 20261022100607_ground_ops_warehouse_indents_read.sql". Snapshot Local-only matches the set; no other version. Prod history unchanged afterwards (959 rows).
